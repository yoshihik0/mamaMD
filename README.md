# mamaMD

**Markdownを、そのまま。**

mamaMDは、Markdownの原文をできるだけ保ったまま読むための、小さなビューアです。

`#` や `**`、リンク先のURLを隠さず、行間と行の長さを整えます。見出し行だけを大きくし、画像をその場に表示します。

本体は [mamamd.html](mamamd.html) の1ファイルだけ。HTML・CSS・JavaScriptを含み、外部ライブラリ、CDN、Node.js、ビルド、APIキーは不要です。何をしているか、ソースを読んで確認しやすいことを大切にしています。

## 使い方

`mamamd.html` を静的なWebサーバーに置き、URLの末尾に読みたいMarkdownのURLを付けて開きます。

主に、同じサイトで公開しているMarkdownを読むためのものです。同じサイト内のファイルは、相対パスでもフルURLでも指定できます。

```text
https://example.com/mamamd.html?articles/hello.md
```

この場合は `https://example.com/articles/hello.md` を取得します。相対パスはビューアを置いたディレクトリが基準です。`?url=articles/hello.md` や、サイトのルートからの `/articles/hello.md` も使えます。先頭には、解決後の完全な取得元URLを表示します。

同じファイルをフルURLで指定することもできます。

```text
https://example.com/mamamd.html?https://example.com/articles/hello.md
```

`?url=` 形式にも対応しています。

```text
https://example.com/mamamd.html?url=https%3A%2F%2Fexample.com%2Farticles%2Fhello.md
```

MarkdownのURLに `&` や `#` などが含まれる場合は、URL全体を `encodeURIComponent()` でエンコードして指定してください。エンコードしたURLを、`?` の直後に置く形式も使えます。

外部サイトのMarkdownもHTTP(S)のフルURLで指定できますが、主な用途としては想定していません。配信元のCORS許可が必要です。`//別サイト/…` のように、相対指定から外部のオリジンへ解決されるURLは受け付けません。

## 表示するもの

| 対象 | 表示・動作 |
| --- | --- |
| 本文 | 白背景で、原文の記号・空白・改行を保って折り返す |
| 見出し | `#` ～ `######` の行を拡大。`#` は残す |
| リンク | URLを表示したままクリック可能にする |
| 同じ配信元の `.md` リンク | mamaMDで続けて読む |
| 外部リンク | URLの横に `↗` を添える |
| 同じ配信元の画像 | 最初から表示。画像のURLも残す |
| 外部画像 | URLと「［外部画像を表示］」を表示。ボタンを押すと読み込む |
| コード部分 | 原文として表示し、リンク化や画像表示を行わない |
| HTML | 文字として表示。タグやスクリプトを実行しない |

本文の先頭には、取得元への直接リンクと `rendered with mamaMD` を表示します。

「同じ配信元」は、読んでいるMarkdownと同じオリジン（プロトコル・ホスト・ポート）を指します。リダイレクトがあれば、その後のMarkdownのURLを基準にします。相対パスのリンクや画像も、このURLから解決します。

一般的なMarkdownのインラインリンク・画像記法と、本文中のHTTP(S) URLを扱います。参照形式のリンク・画像や、表・強調などを含めた完全なMarkdown整形には対応していません。読み取れない記法は原文のまま残します。

## 通信と安全性の範囲

取得した本文は、`innerHTML` ではなくテキストノードとして挿入します。配信元のHTML・JavaScript・CSSを実行せず、ビューア自身のコードだけで表示します。リンク・画像のURLはHTTP(S)のみ許可し、ユーザー名やパスワードを含むURLは使いません。

自動の通信はMarkdown本文の取得と、同じ配信元と判定した画像の取得です。外部画像はボタンを押したとき、リンク先はリンクを開いたときにアクセスします。解析ツールや外部フォントなどは組み込んでいません。

- Markdownの取得にはCookieを送信しません。画像は通常のブラウザーの画像読み込みなので、ブラウザーの設定に応じてCookieが送られる場合があります。
- Refererは送信しません。ただし、画像を読み込んだ相手にはIPアドレスなどの接続情報が伝わります。
- 画像の内外判定は、記載されたURLで行います。同じ配信元の画像URLから外部へリダイレクトされる場合、その転送にはブラウザーが従います。
- 原文の真正性や改ざんの有無、文章の内容、開いたリンク先の安全性を保証するものではありません。

## 読み込めない場合

ビューアとMarkdownが同じオリジンなら、CORSの許可設定は不要です。外部のMarkdownを取得するには、配信元がCORSを許可している必要があります。ビューアをWebサーバーに置いても、この制限は変わりません。

- HTMLページではなく、MarkdownファイルそのもののURLを指定してください。GitHubの場合はRaw URLを使います。
- Cookie認証が必要なMarkdownには対応しません。
- 表示対象は200万文字以下です。

サーバー側の変換処理やプロキシは含みません。Markdownの原文を配信し、読み手側で最小限の表示を加える構成です。
